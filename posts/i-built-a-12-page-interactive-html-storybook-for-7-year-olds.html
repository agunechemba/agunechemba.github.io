I built a 12-page interactive HTML storybook for 7-year-olds.

Because every kid learning to code hits the same wall: the first 20 minutes are magic, then they're staring at a blank Notepad window with no idea what to type next.

So I made My First Three HTML Projects — a web app that looks and feels like a physical book. Warm cream paper, drop caps, a progress bar that fills as you read.

Nine chapters. Three projects, each teaching one new idea:

😜 Silly Face Clicker — a button that repaints the page when clicked
🐉 3-Page Adventure Story — their first taste of files, folders and links
🌈 All About Me Dream Page — pure design, no logic, done alone

The part I'm proudest of isn't the code. It's the teaching. Tags are labelled bricks. Opening and closing tags are a sandwich 🥪. The browser is a very obedient robot 🤖.

And the most important habit in programming gets a name: the Magic Loop — Save → Refresh → Look.

Under the hood: three files, no build step, no dependencies.
→ Progressive enhancement (works with JS off)
→ Quiz answers via native <details>, zero JavaScript
→ Print styles that turn it into a real 12-page booklet
→ prefers-reduced-motion respected

My biggest lesson: restraint is the feature. I wanted page-flip sounds and confetti. All of it would have competed with the content. The book is quiet on purpose.

The most valuable page isn't a project — it's "When something goes wrong." That's what turns a kid who copies code into a kid who debugs it.
