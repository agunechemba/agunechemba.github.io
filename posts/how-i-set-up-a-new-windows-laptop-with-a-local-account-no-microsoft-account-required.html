I recently set up a brand-new Windows laptop, and like clockwork, Windows started pushing me toward Wi-Fi and a Microsoft account before I’d even had a chance to settle in. I didn’t want that. I wanted a plain local username and password—no cloud tie-in, no email link, no telemetry circus. Just a simple offline account on my own machine.

So I went digging. I found two methods that actually work, and I tested them on fresh installs. The first one is the classic trick, but it’s already being patched on newer Windows builds. The second one is the backup that saved me when the first one failed—and it even works while you’re connected to the internet.

Here’s exactly what I did.

Method 1: The classic command (best if you’re offline)

During the initial Windows setup—right after you choose your language, country, and keyboard—you’ll hit the screen asking you to connect to Wi-Fi. Don’t connect. Instead:

  1. Click the Wi-Fi icon on the left so that window has focus.
  2. Press Fn + Shift + F10 on my laptop. On many machines it’s just Shift + F10. If plain Shift + F10 does nothing, try adding Fn—some laptops require it to access the function keys.
  3. An administrator Command Prompt should pop up.
  4. Type this command and press Enter: 
    start ms-cxh:localonly

Windows should then let you create a local account. I entered a username, password, and security question, clicked Next, declined the optional offers, and then said “No” to every privacy and telemetry prompt—Find My Device, diagnostic data, tailored ads, advertising ID, presence sensing, all of it.

The laptop never touched the internet, and when I checked the Start menu, it showed my account as a local account. Under account settings, it confirmed I was a local administrator.

The catch: This method has stopped working on recent Windows Insider builds, including build 26220.6772, and Microsoft is expected to remove it from public releases soon. So if you’re on a newer build, keep reading.

Method 2: The developer console backup (works even online)

This is the method that saved me when Method 1 failed. It’s a little more fiddly, but it worked on the latest Dev Channel build I tested—Windows 11 version 25H2, build 26220.7523.

Here’s the process:

  1. During setup, when you reach the screen asking you to connect to Wi-Fi or sign in, click on the window to give it focus.
  2. Press Ctrl + Shift + J. This opens a hidden developer console. Sometimes it doesn’t appear on the first try—I had to press the keys a few times. So if nothing happens, keep pressing Ctrl + Shift + J until the console shows up.
  3. In the console, type this exactly: 
    WinJS.Application.restart("ms-cxh://LOCALONLY")
    The command is case-sensitive. Some guides show ms-cxh:localonly without the slashes, and both versions have worked for people, but the version above is the one I used.
  4. Press Enter. The console may go dark or seem unresponsive—that’s normal.
  5. Press Escape to close the console. You should now get the prompt to create a local user account.
  6. Enter your username, click Next, and finish the privacy settings as usual.

The best part: this method works even if you’re connected to the internet. You don’t have to disconnect or jump through hoops to stay offline. It just works.

After setup, I clicked my user icon and confirmed it was a local account. I also checked System settings and saw the same thing—local account, local administrator.

The reality check

Microsoft is clearly on a mission to force Microsoft accounts on everyone. The old start ms-cxh:localonly command is already dead in recent Insider builds, and the developer console trick is the current workaround. There’s no guarantee it’ll survive the next update, but as of the latest Dev Channel build, it’s still holding up.

If you’re setting up a new Windows 11 laptop and you want a local account, try Method 1 first if you’re offline. If that fails—or if you’re on a newer build—give the developer console a shot.
